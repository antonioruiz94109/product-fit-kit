# From question to shortlist

1. **Copy the kit.** Choose Use this template on GitHub. One copy serves one product category.
2. **Fit test — gate 1.** Run the fit-test prompt. Any fail on Published, Objective or Comparable means stop.
3. **Write the config — gate 2.** Choose 3–5 decisive spec filters, define measurement edge cases, and review allowed manufacturer domains. Read the generated config before accepting it.
4. **Scope 15–30 models.** Define the market and variants narrowly enough to compare them fairly.
5. **Probe five products.** Extract evidence for just five. If a filter is missing for two or more, demote it to display-only or drop it. Treat inaccessible evidence as missing for this gate.
6. **Full extraction.** Run the extraction prompt for the agreed list. Keep source URLs, exact short quotes and checked dates with every field. Never fill gaps from memory.
7. **Verify independently.** Use a fresh chat or a different AI and the verification prompt. Review conflicts and unresolved retrievals yourself. Run the publish check; it checks records, not the truth of web pages.
8. **Publish — gate 3.** The owner reviews and merges the changes. Only then, with the owner’s approval, enable GitHub Pages from main and the repository root. Re-check evidence every six months.

The supplied shoe sample is a dated demonstration, not a maintained catalog. The 12-month warning is a backstop; it is not a substitute for the six-month review.
